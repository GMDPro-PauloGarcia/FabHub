What's New in v1.7 LATEST

Sales · QS

Version 1.7 (July 18, 2026) adds a proper discount field to the BOQ Builder and clarifies how BOQs are stored and displayed.

💸 BOQ Builder — Amount Discount (before VAT)

The BOQ Builder now has a dedicated Discount field. Enter a peso amount and it is subtracted from the subtotal before VAT is calculated, so the numbers match how our quotations have always worked:

🧮 Subtotal − Discount = Net Total, then VAT 12% is charged on the Net Total. Example: Subtotal ₱154,412.22 − ₱8,000.00 = Net ₱146,412.22 → VAT ₱17,569.47 → Grand Total w/ VAT ₱163,981.69.
  • The Discount (₱ off, before VAT) input sits just under Grand Total in the totals panel
  • A Net Total after Discount row appears whenever a discount is entered
  • VAT and Grand Total w/ VAT automatically recompute on the net figure
  • The discount and net figures flow through to the Preview / Print quotation and the CSV export
  • The deal's pipeline value is set from the net (post-discount) total

This replaces the old "Discounted Total w/o VAT (optional override)" field, which set a manual net figure but did not recalculate VAT. Any BOQ that used the old override is converted automatically on open, so existing totals are preserved.

📂 "No BOQs yet"? Your BOQs are safe — just refresh

Your BOQs live in the database, attached to their pipeline deal. If the BOQ list ever shows "No BOQs yet" when you know you have BOQs, it means your device hasn't finished syncing — the data is not lost.

  • Fix: hard-refresh the page (or log out and back in). This forces a fresh load from the server and your BOQs reappear.
  • A BOQ is created and edited from a pipeline deal — open the deal to find its BOQ if it isn't in the list yet.

What's New in v1.5

All Roles

Version 1.5 (June 7, 2026) restructures how project progress is tracked and how project managers are assigned. Production View is folded into Project Cards. Telegram coverage is expanded across more events.

🏗 Production View Removed — Everything in Project Cards

The separate "🏗 Production View" tab has been removed. Everything you need to manage a project is now in Project Cards — stage changes, team assignment, progress tracking, blockers, updates, billing, and documents are all in one place. No more switching tabs.

📊 Manual Progress — PM Sets the %

Progress percentage on a project is no longer automatically calculated from department task completion. The assigned PM (or Manager) sets the % manually using a slider on the Project Card. This reflects real-world progress rather than a mechanical task count.

  • The slider appears inside the Project Card detail view — only visible to the assigned PM(s) or Manager
  • Moves in 5% increments from 0 to 100%
  • If progress has never been set manually, the display falls back to the old dept-task-based % automatically
  • Setting progress to 100% does NOT auto-close the project — the PM still needs to move the stage to Close-Out

👤 PM Assignment Moves to Project Cards

PM and Coordinator assignment now happens in Project Cards → Project Team → Edit after the project is awarded — not at award time. This is per Mar's process: the OM/GM reviews the project scope first, then deliberately assigns who will own it.

  • At award: PM 1 is optional — you can leave it blank and assign later
  • After award: Manager or Operations opens the Project Card → Project Team section → click Edit → assign PM 1, PM 2, PM 3, Coordinator, Designer, AE
  • When saved, a Telegram notification fires to Ops and Management channels immediately
📌 Rule: No project should move past Stage 07 · Briefing without a PM assigned. The OM/GM must open the card and assign the team before fabrication begins.

Project Cards

All Roles

Every awarded project has one Project Card visible to all departments. Each dept has its own task checklist. Only your department's section can be edited by you — Manager can edit all. Project Cards are the single source of truth for a project's current state.

👥 Assigning the Project Team (OM / GM)

After a project is awarded, the OM or GM opens the Project Card and assigns who will own the execution.

1

2
Find the "👥 Project Team" sectionShows current AE, PM, Coordinator, Designer assignments
3
Click ✏️ EditVisible to Manager and Operations roles only
4
Assign PM 1, PM 2, PM 3, Coordinator, Designer, AESelect from the dropdown lists of available team members
5
Click ✓ Save TeamTelegram notification fires to Ops and Management channels immediately: "👥 Project Team Assigned — [client]"
📌 Process rule: No project should move past Stage 07 · Briefing without a PM assigned. The OM/GM is responsible for making this assignment before the team starts fabrication.

📊 Setting Project Progress (PM or Manager)

Progress is set manually by the assigned PM — not automatically calculated from task completion. This gives an honest, real-world status rather than a mechanical percentage.

  • Open the Project Card → a slider labeled "📊 Progress (set by PM)" appears only for assigned PMs and Manager
  • Drag the slider (0–100%, steps of 5%) to reflect actual site/fabrication status
  • The % is shown on the card grid view and in all reports
  • If never manually set, it falls back to dept-task completion % automatically

🗺 Stage Changes (Manager / Sales)

Inside the Project Card detail view, Manager and Sales can change the project stage using the STAGE dropdown. Every stage change sends a Telegram notification to Sales, Ops, and Management channels.

⛔ Blockers

Any team member can flag a blocker — something stopping the project from moving forward. Opening and resolving a blocker both trigger Telegram notifications to Management and the responsible department channel.

How the Numbers Are Calculated

MetricSource
Revenue BilledBilling milestones grouped by invoice date
CollectedBilling payments grouped by payment date received
ExpensesLogged expenses grouped by expense month
Gross ProfitRevenue Billed minus Expenses
GP%Gross Profit ÷ Revenue Billed × 100
Expenses must be logged using the + Log Expense button in the Finance page. Expenses that are not logged will not appear in the P&L.

Workflow Handoff Chain

The full deal-to-completion lifecycle and who owns each step.

1
Sales creates deal & submits CE requestSales logs the client in the pipeline and requests a cost estimate. Telegram fires to management.
2
QS sets the contract priceSales cannot set the price — QS must price the deal via the CE Queue. The QS home dashboard now flags all unpriced pipeline deals with how many days old they are. Telegram notifies the sales channel when done.
3
Manager reviews at "For Approval" stage (Paulo gate)Only Manager or Sales can push a deal past this stage. Non-management roles can only request an award — not grant it.
4
Deal awarded → Project Card auto-createdOnce awarded, a Project Card is automatically generated with empty department tasks. Team is assigned in Project Cards → Project Team → Edit.
5
Operations executes: submits MRs & BRsOperations submits Material Requests and Budget Requests. Finance (Paulo & Mar) must approve before Procurement can issue any PO. Finance home shows a pending-approvals banner on login.
6
Procurement issues POs & subcon WOsAfter Finance approval, Procurement issues the PO. Designated approvers list (set in Bot Settings) controls who in Procurement can approve their own POs.
7
Warehouse confirms material deliveriesWarehouse sees the project name, contact, and PM name on every delivery card — no more Viber side-channels needed for context. Confirming receipt auto-logs a stock-in movement.
8
Finance tracks billing milestones & collectionsFinance logs billing milestones (DP, progress, final billing) and records payments. Scope Changes are now visible to Finance so billing always reflects the latest contract value.
9
ProjectMover logs daily PM updates & scope changesAssigned PMs post daily updates on the Project Card. Addenda capture approved scope changes. Sales can now view Scope Changes directly — no more AE blind spots on change orders.
10
Close-Out & completionWhen all departments mark done (or PM sets 100%), Manager/Sales can move the project to Close-Out. Final billing is collected and the project is archived.
